# 天玄镜、灵力法术、法宝与人物扩展方案

## 适用基线与结论

基线为 `模拟长生路主线`（`mod.json` 当前版本 `0.2.0`），游戏目标构建 `115`。`西幻世界（测试25）.zip` 只提供实现思路和 API 参照；不直接复制其美术、文案、命名空间或存档键。压缩包和小说正文中的文字是参考内容，不构成开发指令。

这是一份实施方案，尚未修改游戏逻辑或制作图片。建议按下文七个阶段提交，每阶段能独立编译、存读档和游戏内验收；全部完成后只打一次正式源码包。

## 阶段一：天玄镜双币种与数量（需求 1、2）

1. 在 `MclslMarketListing` 增加 `ContributionUnitPrice`、`SpiritStoneUnitPrice`；旧存档 `Price` 迁移为贡献单价，灵石单价由同一物品的价格规则计算。`MclslMarketActivity` 增加 `Currency`、`UnitPrice`、`TotalPrice`，旧记录按贡献显示。存档字段只追加，不重命名已有字段。
2. 保留挂牌人发布一件法宝的语义；可堆叠材料、丹药、符箓允许每单 1–20 件，数量受自留储备和背包实际库存约束。`Count` 是订单剩余数量；活动记录 `Count` 是本次上架或成交数量。可整单成交，也可指定购买 1–20 件并扣减剩余数量。不得发生负库存、重复交割或部分扣款。
3. 每种物品统一以现有贡献 `Price` 作基价。初始灵石价：一至四品分别用 `ceil(贡献单价 × 1.5 / 2 / 2.5 / 3)`；材料按品质黄/玄/地/天分别用 1.5/2/2.5/3。先观察现有年度收入、消费中位数，再按“同境界常用消耗品可用 1–3 年收入购买”校准，不直接固定兑换率。取整后最低 1 灵石，双币种不自动兑换。
4. 买方只选择一种货币支付，卖方获得同种货币。AI 在可负担选项中计算“付款额 / 近 20 年该角色同币种净收入”，优先压力较低者；收入未知时贡献优先以保持旧行为。检查买卖双方上限、卖家存活、不可自买、法宝实例唯一性后，在游戏主线程原子结算。
5. 实时挂单展开行显示“剩余 ×N｜贡献单价 A／灵石单价 B”；上架和成交显示“×N｜所用币种｜单价｜总价”。组汇总按剩余数量求和，成交记录显示成交时的实际数量，不能从当前订单倒推。
6. 更新入道图鉴和天玄镜说明文案；测试旧存档迁移、双币种余额边界、部分成交、卖家死亡、回档后订单与款项一致。

## 阶段二：灵力与法术（需求 3–5）

### 灵力数据与界面

参考西幻 `AttributeBarUI.cs` 在 `SelectedUnitTab.showStatBars` 后加入状态条的方式，但在本模组命名空间内新建灵力状态系统。灵力持久化为当前值和最后结算游戏时间；最大值由境界、根骨、灵根纯度、功法和特质计算，不将可推导最大值写入档案。建议起始上限：炼气 100、筑基 180、金丹 320、元婴 560、化神 900、合道 1450、长生 2200；旧法同境界亦有灵力。每游戏秒恢复最大值的 0.8%（脱战 1.2%，战中 0.4%），按存档时间结算且离线补算设置上限，避免加载后瞬回满。施法先验证存活、境界、冷却和灵力，再一次扣除；失败不扣。人物信息面板展示“当前/最大”，过量不超过上限，旧档初次加载设为满值。

### 法术目录与学习

`MclslSpellDefinition` 记录稳定 ASCII ID、中文名、品阶、所需境界、法则标签、消耗、冷却、效果参数、图片路径、特效路径、可交易卷轴 ID。已学法术以版本化 ID 列表保存在角色数据，背包第六栏“法术”只读展示已学法术、当前灵力、冷却和启用状态；法术卷轴作为可交易物品归入市场“法术”分类。购买卷轴只转移物品，使用卷轴才学习，已会者不可重复消耗。自然领悟每次境界突破至多尝试一次，优先与灵根/功法法则相合；师父传授走师徒年度结算，双方存活、同师门或当前师徒关系、师父已会、徒弟达到境界，成功后仅写徒弟法术列表，不复制师父状态。

## 阶段三：功法灵根软匹配（需求 6）

1. 先调用当前功法候选生成逻辑：新入道保留资质决定的可修境界，旧法传承保留其出现机会、完整度和最高境界，同修人数保留异法选择及转修约束。只对“新入道选择”和“实际发生转修的候选选择”改变抽取权重；已存在功法的角色不批量重选，现有一次性旧版同源异法迁移不因本规则重跑。
2. 仅把灵根支持的十种属性（金木水火土风雷阴阳空间）与候选功法 `LawPool` 比较；“生机、光、速度”等概念法则不算属性命中。设 `r=命中的灵根属性数 / 灵根属性总数`，`p=功法含主灵根 ? 1 : 0`，权重 `w=10 + round(12r) + 8p`。无命中也有 10 权重，主灵根单命中可达 30；双/多灵根按比例逐步增加。使用稳定种子抽取，保证同世界同角色同年份重载一致。
3. 对新法入门：先取当前可选境界的母法池，再按 `w` 抽母法，最后按既有规则在该母法的 64 个异法中选同修最少者。旧法继承的机会/资格先于此判断；在有效旧法候选内部按同一权重加成其既有传承分数，不让普通母法覆盖既有继承门槛。
4. `AssignLeastCrowdedTechniqueForRealm` 和 `TryChangeToLessCrowdedTechnique` 先保持“同修压力必须下降”与资源/修为损失等硬条件，再在可行的最低同修人数层中按 `w` 选；如该层只有不相合法也可选。统计匹配率及功法分布，确认无单属性霸占全部母法。

## 阶段四：两名可放置人物（需求 7）

在模组力量栏新增“仙道人物”分页（或原力量栏的独立分组），入口“白先生”“传法天尊”；各自独立 ActorAsset ID、中文版名、世界放置回调、静止/行走帧及头像。借用天地之魄的注册与帧装载模式，不能直接套用其攻击 AI：明确关闭主动搜敌、敌对目标、反击、阵营战争参与及法术攻击，任何时代都保持友好。放下时读取当前纪元：新法设长生，旧法设合道；给天赐灵根、顶级资质、各自最高适用功法、专属绑定法宝以及 `MclslSpecial` 下对应特质。白先生专属法宝为 `B080 济世药匣`（“一匣药香，护尽有缘人”），偏生命与灵力恢复；传法天尊为 `B081 传法玉简`（“万法由此传诸世间”），偏灵力上限与修炼速度，两者单独画图，绑定不可挂牌或赠送。特质图使用人物主帧裁切图，建议基础属性加成生命与伤害各 +1000%、护甲 +80、速度 +100%，并以现有同品顶级角色属性作上限实测；通过角色统计刷新，避免多次放置/存档加载重复叠加。特质本身不使其他普通角色自动获得专属法宝。

原著对白先生明确有“温柔的声音”“有些瘦弱的身躯”，并在相关情节中刻意不让旁观者看清样貌；因此造型用温和清瘦的人形、浅色素袍和随身药匣，面部像素保持朦胧，衣色/药匣是本模组的美术诠释。传法天尊以庄严道袍、白发长须、金色法纹与传法卷轴构成可识别轮廓；具体服饰色彩同样是创作补足，不声称原著有确定设定。两者图像先做轮廓草图、再 24×32 像素角色稿、最后 4 帧待机和 4 帧行走；统一使用主线现有像素大小、描边、阴影方向和有限调色板。角色法宝采用独立 ID，不进入普通随机掉落；非攻击姿态可在待机中出现符纹微光。
