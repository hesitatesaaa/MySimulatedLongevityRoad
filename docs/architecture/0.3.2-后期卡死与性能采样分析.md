# 0.3.2 后期世界停滞与性能采样分析

## 证据范围

- 本次以 `2026-09-30 07:46` 导出的 `MCLS_perf_20260929_234626_776.txt` 和同次 `Player.log` 为依据。用户提供的 `我的模拟长生路-性能采样.txt` 修改于 9 月 29 日，是较早的采样，不能代表这次 0.3.2 运行。
- 当前样本到仙道纪元 631 年、总人口 6461、修士 2937、原生 10 倍速；已超出原定 4000～5000 人的目标规模。没有该修复版本的游戏内复测数据。

## P1：时间推进而世界停止运行

`Player.log` 中出现约 950935 行“非并发集合被并发修改，状态损坏”异常；其中约 5099 次调用栈落在 `MclslChangeQueue.Publish`。日志约 1.70 GB。最早可见的明确调用链发生于世界第 111 年：

`MapBox.updateSimulation` → `ActorManager.update` → `JobManagerBase.updateBaseJobsParallel` → `BatchActors.updateStats` → `Actor.updateStats` → `MclslPatches.Actor_UpdateStats_LifespanRepair_Postfix` → `MclslRuntimeChanges.Publish` → `MclslChangeQueue.Publish`。

原生人物属性更新在 `Parallel.ForEach` 工作线程运行，而补丁直接读写只允许主线程使用的角色注册表、目标索引、背包缓存、寿命修复集合和变化队列。并发修改会损坏字典；之后重复抛异常使人物更新中断。年份由另一段世界时间逻辑推进，因此出现“时间动、世界不动”。最新报告的年度队列为 0，年度保护系数为 1.00，排除了年度积压保护正在暂停该样本中的原生模拟。

修复将 `updateStats` 回调中的属性修复与变化发布合并成按人物去重、容量有界的线程交接；主线程逐帧处理法宝属性上限、寿命修复与人物缓存变化。其他可能来自工作线程的目标变化也先进入该交接；人物死亡和世界切换会清除对应待处理项。该修复处理的是本次日志证实的直接故障链；尚不能据此声称所有原生并行回调均已完成运行验收。
