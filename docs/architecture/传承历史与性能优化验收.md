# 传承历史与性能优化验收（0.5.2 开发包）

## 本次实现

- 增加“仙道传承”历史分类，修正道统兴衰、功法入录、失传、复现等事件误归宗门遗迹；实体遗迹显世仍归遗迹。
- 设置新增“将传承事件写入原版历史”，默认开启、即时生效。关闭仅阻止以后符合重要性规则的传承消息写入原版历史；玄黄仙录和玩法数据保留，已有消息不删除，重新开启不补发。
- 旧“显示仙道传承公告”保持原有个人法脉额外纪事控制范围，修改说明避免混淆。
- 旧档事件分类按确定的事件类型修正；已有原版消息仅在原档记录仍存在、原始年份/标题/截断正文完全匹配时修正显示，不按标题关键词猜测、不重新广播。无法关联的旧消息保留原状。原版数据库既有行未批量重写。
- 原版历史的 timestamp 是世界秒数，已由直接写年份改为 `(year - 1) * 60`。依据本机 WorldBox 0.51 游戏 DLL 的 Date.getYear/getYear0 核实。历史记录仅保存年，故使用该年开始时刻，不伪造月份。
- 入道回调改为请求首次基础修行；即使其他角色正在年度执行上下文中，也不丢失请求。首次队列与普通年度交替获得处理机会，并利用剩余预算，仍共用约 3ms 帧截止时间、1.5/2.5ms 年度预算及 4096 次保护上限。
- 首次修行与普通年度使用同一真元执行器及已提交年份防重。去除“当前真元为 0 就倒退已结算年份”的修复；新角色不补算入道前年度，积压年份不能被误认为真实世界回档。
- 增量维护未完成首次修行人数和最老等待时间，人数与最老等待查询均为 O(1)，不每帧扫描人口。死亡、失去资格或完成结算后移除；读档由现有候选重建流程恢复请求，等待时间从本次重建开始。
- 首次基础增长后更新感气进度说明；实际突破仍由原年度流程执行。现有生产增长公式保留原来的最低增长规则，没有修改修炼平衡。
- 市场需求构造复用临时集合、排序缓冲和去重索引，保留需求先后顺序；战斗符箓需求改用已有背包计数索引。
- 普通数据和背包变化不再强制重查世界之魄争夺资格；境界、身份、特质、原生资料和世界之魄身份变化仍强制校验。
- 存档复用已验证且仍是同一不可变字符串的前次档案，避免每次保存再完整解析。未知或被替换的内容仍走校验；保留主备档恢复和锁定逻辑。
- 性能报告新增按原生速度分组的全程帧时直方图（0.1ms 上界精度；100ms 以上显示溢出），存档标记帧及后一帧、暂停帧单独计数。原始全程长帧仍保留。明确原有平均值为全程、P95/P99 为最近 4096 帧，避免误把混合窗口当验收数据。
- GC 分配 API 首次使用时校准，识别部分 Mono 环境始终返回 0 的情况并显示“不可用”。

## 尚未验收及实施调整

**以上不是游戏实机 FPS 验收。当前没有 5000 总人口、真实 x20、40 FPS 达标结论，也没有本包修复所有既有存档问题的证据。**

当前世界档案导出引用可变运行数据，本次没有把该对象直接交给后台线程。完整异步存档需要额外的一致性快照设计；此次只实施可验证的重复解析优化，存档仍走原生同步保存边界。跨年度需求缓存也未加入，以免缓存忽略实时生命、法力、战斗状态和市场变化而改变购买行为。

已知旧档若错误记录了“已结算”但实际从未发放，单凭真元为零不能区分它与正常消耗归零。本包不以猜测倒退游标或补发资源；需角色保存数据或明确未提交证据才能制定迁移。

## 实机验收步骤

1. 使用测试存档副本，固定地图、硬件、画质和镜头；分别对照原版基线、旧包、新包，并单独隔离 FunBoost。
2. 新法、旧法分别维持约 5000 总人口、1100–1500 修士、原生 x20；预热 5 分钟，重新开始采样 15 分钟，每组重复 3 次。高修士占比、战争和纪元转换另设压力组。
3. 每组记录开始/结束世界年、已结算年、修士数、首次修行未完成人数、最长等待；比较真实年/分钟和年度积压。不能通过暂停、降速或跳年达标。
4. 主目标：稳定运行 P95 帧时 ≤25ms，结束积压不高于开始；符合入道条件的新修士首次基础结算 P95 ≤1 秒、最长 ≤5 秒（不含玩家暂停、加载）。当前报告提供未完成最长与已完成最大；首次结算 P95 需另行记录样本，不能由最大值冒充。
5. 存读档另测峰值、耗时和回载一致性。直方图只剔除已标记模组存档边界附近帧，其他原生加载/菜单长帧不会自动删除。
6. 检查开关关闭后玄黄仙录继续记录、原版历史不新增传承消息；重新开启后不回放旧事件。退出并重新进入游戏验证设置持久化。

若原版基线已经低于目标，先记录原版/其他模组瓶颈；本包不通过隐藏长帧或修改真实时间倍率伪造达标。
