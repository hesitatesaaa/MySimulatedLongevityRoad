# 0.5.0 世界档案封套

世界档案写入原生 `SaveCustomData` 的 `mclsl.architecture.v2.envelope`，上一份完整档案写入 `.backup`。封套包含格式版本、WorldBox 世界种子、模组运行 ID、递增快照代次、完整领域快照 JSON 和 SHA-256 校验。校验覆盖前述所有字段，读取时还验证内部快照版本和运行 ID 与封套一致。

读取顺序为有效主封套、有效备份；两份均无效时锁定写入并保留原始字节。首次存档会建立主副本；从备份恢复后的首次存档保留该有效备份，之后恢复正常轮换。旧 `architecture.v1` 或无封套的开发期 `architecture.v2` 数据不迁移、不覆盖，要求建立新世界。

原生存档写入前先冲刷人物乾坤袋，再写入世界封套，二者随同一原生存档操作保存。当前 `SaveCustomData` 的两个键没有底层原子替换保证，主副本与校验用于检测和恢复单份损坏。

外部还真空间、轮回档案和猫宝已共用 `MclslAtomicFile`：同目录独立临时文件写入后执行磁盘刷新，再原子替换并保留 `.bak`。替换失败时不退回直接覆盖原文件；读取尝试主档和通过格式校验的备份，两份无效时调用方禁止写入。从备份恢复后的第一次写入保留原有效备份。临时文件不视为已提交档案。

还真外部状态格式为 v9。每个锚点保存完成原生存档后的世界快照代次；待回载记录携带该代次，加载后只有运行 ID、宿主身份与代次全部匹配才注入状态。跨世货币选择使用 `huanzhen-legacy/{遗产}/{选项}` 稳定操作 ID 发行，完整锚点恢复则恢复锚定时钱包，不重复累计。

猫宝独立文件为 `ArchitectureV2/mclsl_maobao_saved_actors_v3.json`，每条记录保存来源运行 ID 与人物 ID；旧猫宝文件不转换也不覆盖。人物模板保存身份、修炼、体质和知识，放置时创建空钱包与空乾坤袋，避免反复放置复制资产。刷新和定位必须匹配当前运行 ID。
