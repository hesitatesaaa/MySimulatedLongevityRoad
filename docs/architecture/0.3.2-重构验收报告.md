## 3. 初始化、完整生命周期、事件与缓存

可追踪的启动顺序：`InterestingTrait.cs:MclslMod.OnModLoad` 加载本地化/配置，注册特质和状态，挂 Harmony，随后 `MclslRuntime.Init` 注册模块和驱动，再初始化 UI。`MclslPatches.MapBox_FinishingUpLoading_Postfix` 重读配置并调用 `MclslRuntime.OnWorldLoaded`；持久化模块优先加载世界档案，随后运行纪元、人物调度及 UI 相关模块。`MapBox.clearWorld`、加载世界前缀和还真回载路径调用清理。主驱动有幂等标记；模块列表只在首次 `Init` 注册。该顺序在源码上合理，**实际补丁全部挂载及世界切换后无旧监听：未验证**。

出生/特质变化从 Harmony 补丁进入注册表和 `MclslRuntimeChanges.Publish`；队列合并 ID，在帧预算内更新人物投影、排行榜和打开的人物面板。死亡后 `MclslPatches.Actor_Die_Postfix → MclslDeathEventRouter.CommitActorDeath → MclslCultivatorCandidateIndex.Remove → MclslActorRegistry.Unregister`，并取消年度任务、变化队列、背包/效果缓存。原生 `Actor.die` 的重入、其他 Mod 绕过补丁和 UI 引用回收需要真实游戏验证。`AddListener` 主要在 UI 节点创建时绑定；人物面板滚动监听在重新绑定前移除；未确认反复开关后监听数保持不变。

完整“建世界→修士→突破→职业→材料→制作→交易→装备/使用→历史/排行→年度→新法→还真→保存→退出→再加载”流程**未验证**。源码存在各节点，现有自动化测试不能替代整链运行。

## 4. 调度、年度结算与新法

主逻辑只由 `MclslRuntimeDriver.Update` 调用。`MclslRuntime.Tick` 以 Unity 帧号去重，变化队列每次最多分发 32 个；`MclslRuntimeCadence.Tick` 以帧号再去重。年度人物管线分 Prepare、Progression、Market、Finalize，各步骤由持久化游标和时间预算推进；世界年度车道分 Prepare、纪元、灾变、洞天、天地变、天地之魄、逆理、探索、功法、宗门、势力、完成。修士出生/死亡期间读取的是 ID 队列，不直接枚举可变人口容器。`MclslScheduler.TryResolveAnnualWorld` 只在候选和年度角色待办清空后推进，并且**该车道自身**按年份顺序完成。

但 `MclslModuleHub` 的年度模块使用独立 `NextYear/LatestYear/CompletedAnnualYears`，回调一返回就记完成，不等待 `MclslScheduler` 真正完成该年份。不同模块轮询可能先结算后一年，再由世界车道继续前一年。详见 P1-02。目标级失败隔离存在；模块级异常会直接记录完成并跳过，详见 P1-03。异常后的实际副作用/存档恢复一致性未验证。

新法切换由 `MclslWorldEpochSystem.EnsureAnnualState → ProcessTransitionYear → ScheduleAncientCultivatorQueueSeed → TickDeferredTransitionWork` 完成；旧法修士用 `AncientLawProcessed` 防重复转换，转换每帧有 0.45 ms/数量预算。旧法已转化者仍可作为遗修继续存在，不能简单判定为“双轨”。新法专属洞天、天地变、逆理、势力事件等会增加年度负载；`MclslCultivationCatalog.TryTechnique` 使用 LINQ 线性查表，功法传承结算有按目标重复遍历法脉集合的路径。**新法掉帧真正原因未验证**：需要同时记录当帧系统耗时、GC、排行/UI 状态，不能把这些源码候选写成已确认根因。

## 5. 玩法链、还真与 UI

物品路径静态可连通：目录定义→材料/制作/掉落→`MclslBagSystem` 数量栈或法宝实例→天玄镜挂单/购买→`MclslItemUseSystem` 或 `MclslArtifactSystem`→档案/公告。制作与市场会建立材料保留计划；无职业分支只考虑成品/卷轴。法宝装备位保存在六槽引用，并刷新原版状态效果。丹药持续效果有有界延迟队列，符箓消耗走同一使用入口。这些是**源码路径确认**，真实装备属性、丹药数值、符箓扣减与交易所有权守恒仍未验证。物品效果采用按 ID 的 `switch`，统一数据模型尚未完全覆盖效果执行。

还真 `TickAnnual` 调用 `SettleNaturalEssence`，按到期十年周期数一次结清；最多三枚锚点，遗产可选数量取现有锚点数。回载用世界运行 ID、宿主身份、锚点路径及有界重试校验；新世界清理运行态，空间灵蕴存外部状态。真实“保存锚点→死亡→载入→保留选择→再运行”未验证。

排行榜使用增量有序索引，但显示中的每次人物变化仍触发可见卡片整批回收；列传快照分帧；背包、玄黄仙录、特性窗口多有 `visible/isActive` 防护。UI 打开、数据变化、滚动、关闭、重开，以及重复监听/节点数，需要实机逐页验证。
