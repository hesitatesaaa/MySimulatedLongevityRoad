# 0.5.0 架构、数据所有权与年度流程

## 分层与所有权

| 层 | 主要类型 | 唯一职责 |
|---|---|---|
| 游戏适配 | `InterestingTrait`、`Interop`、`Patches` | 接收 WorldBox、Unity、NML、Harmony 和原生存读档事件 |
| 世界上下文 | `MclslWorldContext`、`MclslWorldRunRepository` | 建立世界代次，持有当前领域状态和索引 |
| 领域数据 | `MclslArchiveData`、`MclslEconomyState`、物品/家族/还真状态 | 保存强类型事实，不执行 UI 或原生对象操作 |
| 规则与命令 | 修炼、体质、制作、市场、探索、死亡系统 | 验证规则并生成一次可提交的状态变化 |
| 调度与存储 | 年度人物管线、年度世界车道、经济事务、封套 | 分步推进、幂等提交、失败隔离和完整快照 |
| 查询与展示 | `Queries`、`UI` | 从投影读取，不触发玩法结算 |

原生移动、地形和战斗对象仍由 WorldBox 管理。模组领域状态是修炼、物品、经济、关系和世界纪事的权威来源；原生特质及人物扩展字段是同步边界或查询投影。所有 Unity 和 WorldBox 对象只在主线程访问。

## 年度流程

每个结算年按以下顺序推进：世界准备与只读快照、人物规则、跨人物事务、经济计划与制作、市场撮合、世界事件与家族收尾、完整年度提交。每个工作项包含年份、领域、实体、步骤和稳定操作 ID；游标与状态一起保存。单个大任务在内部按人物、法脉、家族成员、挂单或探索者继续拆分。

调度器每帧以 3 ms 为初始总预算，并按帧压力减少每步数量。压力调整只影响模组工作吞吐，不修改 WorldBox 时间倍率。年度世界车道在各领域间固定轮转，失败最多重试三次；一致性失败保留年度未完成状态并记录隔离信息。

## 体质与灵根命令

`CanOwnSpecialPhysique` 与修炼资格分离，实时读取人物 `isSapient()`，且拒绝模组自定义实体。授予顺序固定为资格验证、添加体质、以持久化稳定随机键确保完整灵根、刷新候选和界面。已有完整灵根不会重抽；移除体质不会删除灵根；失去智慧资格时对账移除体质。恢复期间原版亚种尚未初始化时延后判断，避免误删或永久跳过出生抽取。

## 经济事务

经济操作分为发行、转移、消费、回收和销毁。事务先验证账户、余额、溢出、库存、挂单和托管，再提交钱包与领域状态；人物效果发生异常时恢复快照。市场学习卷轴、历史和通知在成交提交后执行。死亡卖家先进入家族遗产清算，无家族时托管转公共库存，余额按死亡清算规则销毁。

同一年度的 `InventoryPlan` 同时决定自用保留、生产预留、采购和可售量。职业每年只成功制作或练习一次，商业备货目标为 2，练习消耗一份所选配方材料并取得一半经验。价格以实际材料机会成本加 25% 工时为参考，五年有效供需只在有资金支持时推高需求。

## 存档边界

世界档案只写 ArchitectureV2 完整提交点，不读取或覆盖 0.3.5 数据。封套校验世界种子、运行 ID、代次、格式版本和 SHA-256，并保留上一代有效备份。还真外部锚点保存世界快照代次；猫宝 v3 保存人物模板但不保存钱包、普通物品或法宝实例。
