## 3. 回归步骤与判据

### R0 启动冒烟
- 步骤：启动游戏 → 启用模组 → 进入主菜单 → 新建世界（中等地图即可）。
- 预期：模组加载成功；日志中**无** `Failed to compile mod` / `Required Harmony patches failed` 等初始化失败；无红色异常堆栈。
- 证据：日志片段（加载段）+ 主界面截图。

### R1 诊断开关
- 步骤：设置里确认"诊断日志"= 关 → 正常推进若干年（如 5–10 年）→ 记日志 A；再把开关打开 → 再推进若干年 → 记日志 B。
- 预期：日志 A **无** `[诊断]`、`[probe]` 输出；日志 B 出现 `[诊断][probe]` 等，但每个 key 只出现一次、不刷屏（60s 节流）。
- 证据：日志 A、日志 B 各一段（含开关状态说明）。

### R2 关键日志仍可见
- 步骤：在"诊断关闭"状态下，触发一个已知告警（例如地图标记缺资源，或存档目录只读/占用导致读取失败）。
- 预期：仍能看到 `[模拟长生路][存档]` / `[还真]` 的告警/错误（Alert/Fatal 不受诊断开关影响），文本与改动前一致。
- 证据：对应日志片段。

### R3 初始化去重（核心）
- 步骤：① 新建世界后运行数十年；② 存档后重进读档；③ 切换/重载另一个世界。
- 预期：修炼/市场/榜单/还真/妖兽等核心系统正常；**无**重复初始化副作用（如同一数据条目翻倍、初始化日志异常重复、年度结算加倍）。`WriteLocked` 场景：把主档设为只读后再加载，应拒绝写入并保留原档、不崩溃。
- 证据：三次操作后的截图 + 关键系统数值说明；如触发 WriteLocked，附日志。

### R4 年度推进无刷屏
- 步骤：连续推进 ≥ 50 年，观察日志与帧率。
- 预期：无 `空 catch` 批量刷屏；无异常 GC/卡顿尖峰（主观记录）。
- 证据：50 年推进后的日志尾段 + 帧率/耗时截图（`tools/runtime-benchmark.ps1` 若适用）。

### R5 保存/读档
- 步骤：保存 → 退出 → 重进 → 读档。
- 预期：世界状态、模组数据完整。
