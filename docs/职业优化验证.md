# v0.3.1 职业降阶限产与熟练度调整

修改范围为本主线工作区。沿用 0.3.1 版本，保留既有排序、年度交易及年度性能优化。

## 制作规则

炼丹师、炼器师、制符师共用职业制作策略：每名修士每个结算年最多成功制作一件，优先同阶，缺料时最多降一阶。按流水线传入的实际结算年 Y，统计 Y−4 至 Y 的成功降阶制作，全部物品合计最多两件。跨配方、更换职业或晋升均不重置；同阶制作不占额度。额度用尽时，选方和材料需求均跳过降阶配方，仍可制作同阶物品。

| 成品品阶 | 同阶熟练度 | 降阶熟练度 |
| --- | ---: | ---: |
| 凡阶 | 1 | 0 |
| 黄级 | 3 | 0 |
| 玄级 | 6 | 0 |
| 地级 | 10 | 0 |
| 天级 | 15 | 0 |

最高职业品阶为天级，因此正常选方不会产生天级降阶成品；策略对任何降阶成品均返回零收益。累计晋升门槛仍为 10、30、80、160，原有境界要求保留。按制作前职业品阶计算本次收益，再执行晋升，避免本次成品因晋升变成降阶。持续同阶成功制作且境界充足时，理论晋升周期为 10+7+8+9=34 年；缺料、降阶、境界不足会延长周期。

## 数据与失败处理

角色数据新增 `mclsl.profession.lower_craft_older_year` 和 `mclsl.profession.lower_craft_newer_year`，保留最近两次成功降阶制作的结算年。缺项读取为 −1，从更新后开始记录，不补发历史熟练度。已有熟练度、职业等级、库存、挂单均保留，不清理截图中的存量物品。

制作前检查年度成功标记、配方品阶、滚动额度及两份材料。普通缺料、无合法配方或额度不足会在扣料前返回，不记录次数或熟练度。成品交付后立即写入成功年份和降阶年份，再计算熟练度、晋升及执行装备/历史回调，防止可选回调异常导致同年重复制作。沿用既有流水线乾坤袋事务。

新增字段属于 `mclsl.*` 角色数据，猫宝快照通过 `MclslActorDataKeys` 反射捕获，已有前缀允许规则自动覆盖，无需另设白名单。已通过生产快照捕获、JSON 序列化及回载代码验证。普通 WorldBox 存档继续由角色 custom_data 保存这些整数；真实游戏保存流程仍需游戏内复测。

## 实测范围与限制

没有启动 Unity 进行真实角色制作、扣料异常注入、年度处理中保存重载及职业切换操作测试；独立回归使用生产策略和快照代码，底层游戏角色存储由最小桩替代。不能将这些结果表述为游戏内交割或整档恢复已经实测通过。

用户提供的 Player.log 未发现职业炼制异常堆栈，不包含本次修改前后的性能采样。未报告帧率改善。截图的排行榜标题为“按综合战力排序”，初期修士因战力更高排在中期之前符合该排序；查看大小境界顺序需选择境界排序。

游戏内复测应使用存档副本，验证成功降阶两件后第三件缺料前拒绝，第六年额度释放；分别观察丹药、法宝、符箓，以及晋升和职业切换；在年度处理途中保存并回载，检查成品、材料、熟练度及成功年份均一致。现存低阶库存不会自动减少，限产效果随后续结算年份体现。
