# v0.3.1 排序、交易与年度优化

修改范围：本工作区主线源码。保留 mod.json 的 0.3.1 版本及已有玩家设置。

## 行为变化

- 境界排序按大境界、圆满/后期/中期/初期比较；太上高于长生，凡俗最低。反向排序同时反转大小境界。同一小境界按其他排序条件及原有战力/角色 ID 兜底，不比较具体修炼进度。
- 正常、降级及最低降级快照均填充小境界排序字段；角色存档格式不变。
- 修士每年最多成功交易 20 笔，每次流水线步骤仍只交割一笔。订单中的物品件数不改变笔数。旧存档当年已买 6 笔时仍记录 6 笔，可继续购买；跨年使用新年度额度。
- 幼年灵根默认 10%；三职业分别默认 10%，保留原有一次性、互斥判定。职业配置以 0.1% 为单位，默认滑块值 100，转换为运行时 1000 基点。新安装、缺项及恢复默认使用新值；已有配置原值继续加载，已经完成的人物判定不重置。

## 源码确认的性能风险及修改

1. 年度启动原先在一个调用中对全部市场挂单检查卖方存活。市场挂单上限 1000，这些角色查找与清理会集中在年度启动帧。现改为按稳定挂单 ID 分帧清理，每帧最多 16 条，并受 0.15ms 的自适应时间预算约束。时间检查位于循环内部，至少允许处理一个目标，单次目标调用本身不可抢占。检查完成后才继续年度角色撮合，保留清理在交易之前的顺序。
2. 清理年份、目标 ID 列表及游标写入年度批次。中途保存后继续剩余目标，已经删除的订单不重复处理；单目标异常记录失败后继续其余目标。旧档缺少字段时安全初始化，迁移会规范空列表及游标边界。市场索引首次重建仍是同步操作，没有把全部年度工作宣称为可抢占。
3. 周期存档原有延期条件未覆盖世界年度阶段，可能与世界阶段重叠。现检查所有年度积压和活动年度，并记录 Unity 帧号；年度工作最后一帧及其后一帧内不执行周期存档。显式保存仍同步完成；写入失败不清除脏状态。切换世界清除延期状态。
4. 整体档案导出和 JSON 序列化仍同步执行，超大档案仍可能造成保存长帧。没有把活跃的 Unity 对象交给后台线程，也没有以缩减玩法代替优化。
5. 天玄镜关闭时原本就不绘制，打开时暂停模拟。现在仅打开时读取挂单、动态和年份，复制为独立文本快照；分类、页签及展开卖方复用快照。绘制采用固定行高和二分查找，只绘制可见区及约 220 像素缓冲；关闭、销毁或运行档案替换时释放快照。挂单分组改为一次遍历，卖方名字在打开期间按 ID 缓存。后台上架、交易与年度撮合独立运行。
6. 限购增加会增加撮合步骤，职业比例调整也会改变生产量；这些成本仍需对修改后的同一存档实测。不能仅凭较低灵根默认值推断整体帧率收益。

## 诊断能力

保留现有世界年度阶段、年度周期总耗时、P95/P99 帧时间、GC 分配、人口、队列积压及档案序列化探针；补充年度启动子步骤、分帧市场清理、职业需求生成、挂单查找交割、市场打开快照及可见行绘制采样。诊断未开启时不创建动态年度启动采样名。

未捕获本次修改前后同一存档的 Unity Profiler 或游戏内性能探针数据，不能判定玩家机器上唯一/最大的实际热点，也不能报告 FPS 或毫秒改善。其他一次性世界阶段仍保留现有行为，待采样确认热点后再拆分，避免未经证据改变其结算顺序。

## 尚待游戏内验证

独立回归没有启动 Unity，因此不能替代以下测试：实际物品/货币交割及交易异常恢复、连续跨年积压消化、年度处理中真实世界保存重载、世界切换、排行榜降级角色读取、天玄镜不同分辨率的滚动和展开布局。

性能复测应使用同一存档副本、人口、视角及速度，分别运行旧代码与新代码，每组至少覆盖多个年度并重复采样；比较最长帧、P95/P99、GC 分配、年度周期耗时与请求年/最旧未完成年差值。窗口关闭、窗口打开和大量挂单分别记录；打开市场时暂停模拟，必须单独比较 UI 渲染成本。若队列持续增长，降低峰值本身不能作为通过标准。

开发者构建中，可在开发者人物编辑器使用“开始性能采样”和“停止性能采样”，停止时导出到游戏持久化目录中的“我的模拟长生路-性能采样.txt”。正式源码型包不含 DeveloperTools。
