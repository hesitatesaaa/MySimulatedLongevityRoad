# 2026-11-05 修复记录（排行榜战斗职业排序 · 游戏卡住）

## 一、排行榜新增「战斗职业」可选排序

需求：排行榜右侧「可选排序」增加按战斗职业分栏，每个职业内部从高到低排序。

实现：
- `MclslRankEntry` 增加 `CombatCareer / CombatCareerRank / CombatCareerExperience` 三个快照字段（`-1` 表示无战斗职业）。
- `MclslRankSnapshotSource` 在三条建表路径上统一用 `ReadCombatCareer(actor)` 一次读出职业、阶位与熟练度（避免排序时反复取档）。
- `MclslRankWindow.SortDefs` 新增六项：剑修、武修、术修、符修、阵修、灵契师，图标用 `trait/MclslCombatCareer_<id>`。
- 首排序为该职业时走 `CompareCombatCareer`：按阶位（宗师→未入门）降序，再按熟练度、境界、战力、稳定 ID；无该职业者沉底。
- 该类排序固定为「高到低」，不参与升降序切换（与炼器/炼丹/制符职业排序一致），并补充了对应悬停说明。

## 二、「游戏卡住，只有时间动、世界不动」——原因与修复

### 日志证据

分析玩家日志 `Player-prev.log`（约 15 MB / 149,881 行）：

- 全程共 **9,303 条 NullReferenceException**，其中 **9,296 条**栈顶为：
  ```
  Actor.checkCalibrateTargetPosition()  (Actor.cs:539)
  ← Actor.u10_checkSmoothMovement ← BatchActors.u10_checkSmoothMovement
  ← Batch.runUpdater ← updateJobsPost ← JobManagerBase.updateBase
  ← ActorManager.update ← MapBox.updateActors ← MapBox.updateSimulation
  ← MapBox.checkMainSimulationUpdate ← MapBox.Update
  ```
- 该异常从世界加载后不久（日志第 808 行）开始，一直持续到结束，稳定出现。

### 根因

原版 `Actor.checkCalibrateTargetPosition` 在「行为目标」是 Actor 类型时，直接取
`beh_actor_target.a.current_tile.x/y` 以及 `this.tile_target.x/y`。当某个单位的行为目标
**没有落在地图格**（`current_tile == null`，例如刚创建/已离开地图/被模组创建但未就位的目标），
就会抛空引用。

这个异常发生在 `ActorManager.update` 的批量更新（`Batch.runUpdater`）内部。一旦抛出，
本帧该批次剩余单位的更新全部中断；而它每帧都触发（目标一直是坏的），于是**单位几乎不再更新移动，
但 `MapBox.Update` 仍在推进日期** —— 正是「时间在走、世界不动」。

### 修复

1. **行为目标空引用守卫**（`MclslPatches`，Harmony 前缀）：
   `Actor.checkCalibrateTargetPosition` 执行前检查 `beh_actor_target` 指向的 Actor 是否有
   `current_tile`；无地图格时清空该行为目标并跳过本次校准，`tile_target` 为空时也跳过。
   这样既避免每帧空引用中断整批单位更新，又顺手清掉坏目标（自愈）。
2. **年度回压不再把世界时间乘成 0**（`MclslAnnualSpeedPolicy`）：
   原最高档 `factor=0` 会让单位与世界完全停摆，而年度结算又依赖世界推进才能消化积压，形成
   只能读档的死锁。现最高档保留 `0.25x`，任何档位都不会冻结世界。
3. **年度结算阻塞自愈**（`MclslWorldRunRepository.AnnualFailures`）：
   原 `WorldBlocked` 一旦置位在任何地方都不会复位，年度世界（时代/兽潮/宗门/家族…）永久停摆。
   现增加有界指数退避重试（最多 8 次），并在进入世界/读档时清除上次遗留的阻塞状态。
4. `MclslAnnualBackpressure.IsBlocked` 改为空安全，避免取档期间的空引用。
