# 感气停滞与年度积压修复验证

日期：2026-09-28。修改范围为“模拟长生路主线”，Mod 版本仍为 0.3.1。保留此前境界排序、20 笔年度限购、默认10%概率和职业降阶限产/熟练度调整。

## 已确认原因

旧存档世界显示776年，世界年度已完成629年、待处理630年，最新请求777年。185名有根角色中180名无境界且零真元，全部在 Prepare.0，角色待处理年份晚于世界年度门禁。卢望远从709年等待，诸葛江宁从719年等待。详见[只读诊断](感气停滞原因检查.md)。

源码确认的放大因素是未来年份角色不断出队再回队、每个年度重复刷新完整注册表、调度器低频处理和多路独立预算。旧日志还确认 Prepare.5 职业单步曾出现33～150ms，Prepare.2 自然赠予约108ms，Market.0 约40ms。这些日志属于已有构建；不能作为本次修改后的性能结果。

## 最终实现

- 一份角色状态字典，配合独占可执行队列与按年份排序的等待桶。每步公平轮转，释放最多64人且受剩余预算限制；角色死亡、资格变化或引用失效清除成员。队列节点有界复用，减少每步反复分配。
- 年度只使用候选ID快照，取消每年度全注册表刷新；年龄、特征和修炼身份事件继续登记。读档一次分帧重建；每120渲染帧按稳定ID队列审计至多64个已注册角色，审计不制作、交易或发真元。
- 独立驱动每渲染帧给予一次处理机会，Unity帧号去重。启动续跑、候选入队、等待释放、角色步骤及世界阶段使用同一预算：1.50／1.00／0.75／0.50ms。角色数量上限配置保留。世界阶段移除额外低频等待；即使角色队列为空，待处理世界年份仍保持调度资格，保证世界启动重试继续进行。
- 新增世界档案 StartCursor，保存启动阶段。旧档缺项从0恢复，越界值夹至0～7；读档另外恢复运行时侦测和探索登记。运行时队列不另存，沿现有角色阶段和年份重建。
- 职业配方静态按类别和品阶预分组并按ID排序；已知配方数组使用现有弱引用知识缓存，知识变化即失效。材料需求和制作复用候选数组；材料、年度成功标记和降阶限额仍重新校验。没有缓存库存是否充足的结论。
- 精确挂载 MapBox.updateSimulation(float) 前缀，缩放本次步长或暂缓该次调用。不改倍速选择、Config.paused、Time.timeScale，不积累时间债务。保护挂载失败计入关键补丁失败并显示中文提示。
- 恢复阈值5／3／1年，各需非缩放时间稳定两秒；压力加重立即升级。核心关闭、设置关闭、世界切换清空保护。
- 显示世界年、完成年、积压、可执行/等待人数和时间系数，仅状态变化公告。性能报告增加步骤/秒、年份/秒、最长等待年差和首笔真元最大等待秒数，并增加职业内部与自然赠予采样。

积压计算使用 max(实际世界年, 最新请求年) - 世界已完成年。因此上述旧档保护判断为148年，不直接改写任何完成年份。原有逐年提交标记、职业成功年份、交易计数和奖励游标继续生效。移除旧的“最多补十二年”缺年截断，真实增长年份与完成游标不一致时逐年补算。
