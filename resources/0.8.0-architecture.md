# 0.8.0 运行架构与接口

本说明描述已落地的结构，不代表整项目已通过发布验收。实施状态和证据范围见 refactor-080-progress.md。

## 生命周期与所有权

InterestingTrait 初始化原生资产、注册状态和补丁，再启动 Runtime 与 UI。全部 Harmony 补丁使用同一个拥有者，加载失败时撤销该拥有者补丁。资产注册失败后的完整回滚仍需复查，不能视为已经完成。

MclslWorldContext 保存当前世界标识和进程代次，时钟读取原生世界时间。Runtime 负责载入、每帧推进、保存和清理；不再由 Modules 模块框架各自组织生命周期。线程回传带代次和对象引用校验，换世界后旧对象不能进入新索引。

MclslActorRegistry 是单位引用的统一入口，每个人物的引用、版本、原生快照与目标快照保存在同一注册记录，不再分散维护多份按人物索引的字典。目标本身未变时不提交人物更新；工作线程通过只读注册入口及每人物目标快照交接。ActorRelations 持有原生家族、亲子和亚种关系；CultivatorCandidateIndex 持有当前修炼资格、年度候选及境界分桶；BeastPopulationIndex 维护妖兽来源和区域计数。查询不扫描人口来补齐索引。

## 变更与预算

MclslRuntimeChanges 合并同一人物的变更标志。原生工作线程只提交通知，主线程交替处理原生通知和派生更新。只有关系、特征或原生元数据变化才更新家族、颜色和关系索引；背包或余额变更不会重新判断原生家族关系。

MclslFrameDeadline 提供共享帧截止时间。变化分发在其份额内持续消费，年度调度同时使用共享操作预算。每名角色一轮最多推进四个微步骤，未完成者排到其他角色之后；不能用反复调整多个批次数来相互压低吞吐。

Scheduler 组织年度启动、候选、角色阶段和世界阶段。角色运行游标保留在内存，PrepareForSave 在原生保存前写入所有待办游标，包括尚未首次执行的任务。异常保留步骤并报告失败，不自动跳过或无限重试。暂停可以结清已有年度工作，不制造新年份。

## 地表与家族

BeastSurfaceIndex 初建时建立区域水陆候选；原生地块修改只更新该地块。仅改变生物群系而没有改变水陆分类时，不更新索引。自然生成沿用现行概率、数量和事件限制。手动召潮提交请求后优先分帧准备，按钮回调不扫描地图。

FamilySystem 使用待处理成员、受影响家族和活跃家族集合。无修士无事务时休眠；凡人仍参与存活、归属与遗产。失去修炼资格只退出修士职责，不删除境界。五年结算只捕获到期的活跃家族。

按本轮确认，全员离族后先完成原有灭族清算，成功后删除旧族和历史；重新入族使用新标识。未完成清算的删除意图属于持久事务状态。正常死亡绝嗣的历史记录沿用原有玩法。

## 战斗、显示与资源

CareerCombat 和 BeastTalentSystem 只维护活跃施法者及持续效果。普通待命中法术按下一阶段时间排序，未到期任务不逐帧遍历；到期后移除或重排。保存继续使用强类型待命中状态，净化同时移除已到期及未来的对应持续伤害。

自用法术只索引拥有相关法术的角色，使用已有有序索引避免死亡空槽。冷却与持续时间沿用世界时钟。

界面大图放在 InterfaceResources，通过原 NML 图片加载器按需读取，原图字节及显示参数保留，避免作为 GameResources 被全部预加载。图片实际文件归属由资源清单 File 字段声明。国家色资源按实际使用准备，新增颜色分批生成；跨世界清理拥有的 Sprite、Texture 和准备任务。WindowPause 由窗口持有者共同管理，最后一个窗口释放时恢复原生进入状态。完整视觉复查仍需真实渲染记录。

## 存储与交付

0.8.0 世界键前缀为 mclsl.080.，外部目录为 MySimulatedLongevityRoad/0.8.0，不读取旧模组格式。保留本版还真、传承和收藏玩法。资料写入使用必要的原子提交边界，暂存索引不保存。

release_inputs.py 定义玩家包输入，打包和验收指纹共用该清单。源码由 NML 编译，开发探针与构建目录不得进入生产输入。压缩只修改包内副本；正式交付还必须具备当前输入、原生程序集及最终包哈希所对应的功能、视觉、兼容和性能证据。

实施日志属于证据材料，不回流进生产输入指纹，避免记录测试结果反过来改变被测输入。最终 ZIP 哈希仍覆盖全部包内文件。
